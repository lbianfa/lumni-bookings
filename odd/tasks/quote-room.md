# quote-room

Status: closed (2026-10-26).

Objective: the "Quote a room" page (`design/Main.dc.html`) end to end: `POST /api/quotes` with the CONTEXT §1.1 rules, the rooms catalog, and the SPA screen. The 3-step booking flow is out of scope.
Branch: `main` (user convention: work-unit commits directly on main, no PR). Delivery: commits per work unit. Test runner: none, by user decision (no tests in ODD features); checks are structural (`tsc`, build, lint) plus manual probes (curl, browser).

## Specs

- **S1** — Scope: implement only the quote room page, without the booking flow and its three steps. The "Start booking" action is not wired yet. *Assumption:* the button is left out of the page until the booking feature exists.
- **S2** — Availability uses a minimal `bookings` table created now (user choice: minimal bookings table): `id`, `room_id`, `starts_at`, `ends_at` (`timestamptz`), `status` (`draft`/`confirmed`/`completed`/`cancelled`), `created_at`, `updated_at`, plus the D-05 exclusion constraint (`btree_gist`, room + `tstzrange(starts_at, ends_at, '[)')`, statuses `confirmed`/`completed`) added as `rawSql` in the migration. No booking flow writes to it yet; the booking feature extends it later with a new migration. *Assumption:* `customer_id` and the other booking columns are deferred to that feature.
- **S3** — Rooms (resolves P-02): 12 seeded rooms following the recommended pattern (user choice). *Assumption on the split:* small `Room S1`–`Room S5` (capacity 4, COP 40,000/h), medium `Room M1`–`Room M4` (capacity 8, COP 70,000/h), large `Room L1`–`Room L3` (capacity 16, COP 120,000/h). `rooms`: `id`, `name` (unique), `size`, `hourly_rate` `numeric(14,2)`, `capacity` (D-12, D-13). The seed upserts by name.
- **S4** — Date rule (new decision D-21, user choice): quoting a slot that starts in the past is not possible; there is no limit on how far ahead a customer can quote. When choosing the start time, the page offers only the times within that day's opening hours, and for today only those not yet passed. "Now" comes from a `Clock` port in `America/Bogota` (D-02).
- **S5** — `POST /api/quotes` (session required) receives `roomId`, `date` (`YYYY-MM-DD`), `startTime` (`HH:mm`, 30-minute grid) and `durationMinutes` (60–600, multiples of 30). Pricing per CONTEXT §1.1: `base = rate × hours` → duration discount (10 % from 4 h, 20 % from 8 h, highest tier only) → Saturday surcharge 25 % over `base − discount` → `total`; amounts keep cents (D-13). The response carries the breakdown, whether booking is possible and, if not, the reason and the next free slot on the same day for that room (half-open intervals; only `confirmed`/`completed` block, D-04). Malformed input → `400`; unknown room → `404`.
- **S6** — `GET /api/rooms` (session required, thin feature) returns the rooms ordered by size and name, for the room picker.
- **S7** — SPA: the quote page follows `design/Main.dc.html` (room picker grouped by size with rate, date, start time, duration stepper in 30-minute blocks, rules strip, quote panel with breakdown, available / not-available states and the "Use HH:mm–HH:mm" suggestion). The selection lives in component state, not in the URL (user correction, L6). The authenticated layout header gains the "Quote" navigation link from the design.
- **S8** — No tests in this feature (standing user rule). Prisma commands (contract emit, migration plan/apply, seed) are run by the user; the agent hands over the exact commands.
